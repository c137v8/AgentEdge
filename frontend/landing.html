Overview

Agentic commerce today mostly means an AI that fills a cart and then hands you back to a UPI PIN screen anyway — the friction it promised to remove is still there at the one moment that matters most.

Agentic Checkout removes that last mile. A user blocks a spending limit once, in a single real Razorpay authorization, with a hard per-transaction cap and an expiry. From that point on, the agent can search, add to cart, and check out entirely in natural language — no dialog boxes, no repeated authentication, no "approve this payment?" interruption per purchase.

It's the pattern behind Razorpay's own UPI Reserve Pay (Single Block, Multi Debit): block funds once, spend many times, safely.

AI shopping, in plain language

"Show me earbuds under 3000." "Add the mechanical keyboard." "Checkout." That's the entire interface.

A LangGraph agent interprets intent, resolves it against a real product catalog, manages a live cart, and only ever proposes a purchase — it can never execute one unilaterally. Every checkout ends in an explicit, tap-to-confirm card in the chat itself, so the human is always the one who pulls the trigger, even though everything up to that point was zero-click.

Gemini handles the natural-language layer; a deterministic rule-based fallback keeps the app fully usable even with no LLM key configured at all.

Guardrails that can't be talked around

An agent that can spend money needs limits an agent can't argue its way past.

Every mandate carries a hard block amount, a per-transaction cap, and an expiry, enforced by a single choke-point function that is the only code path in the entire project allowed to move money. Try to check out above the cap, and the agent refuses and explains why — not because a prompt told it to be careful, but because the guardrail is structural, not conversational.

Every attempt — successful, blocked, or refused — lands in an auditable ledger the user can see in real time.

Speaks the Agentic Commerce Protocol

Execution goes through a real checkout-session lifecycle, not a bespoke one-off endpoint.

The transactional layer implements ACP — the open standard co-developed by OpenAI and Stripe for how an agent, a buyer, and a merchant complete a purchase — as real REST routes: create, update, retrieve, complete, and cancel a checkout session, with ACP's own error shape and versioning header. Whether the request comes from this app's own chat-driven "Confirm & Pay" button or an external ACP-speaking agent, it goes through the exact same execution path.

Secure by default, honest about the rest

No API keys checked in, no keys required to try it.

If the server has no .env keys, the app asks for them in the browser instead — held only in server memory for that session, never written to disk or logged. Skip the prompt entirely and the app drops into a fully local test mode: a rule-based agent, a simulated payment rail, and a persistent on-screen ribbon making it unmistakable that nothing being shown is a real charge.

The project is equally upfront about what's simulated elsewhere — see the README's "what's real vs. simulated" table. Nothing here is exaggerated to look further along than it is.
